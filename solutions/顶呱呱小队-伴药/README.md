## 项目背景
发作性睡病是一种慢性中枢神经系统疾病，核心问题是睡眠-清醒节律调节障碍。患者可能在课堂、会议、走路甚至骑车时突然入睡，也可能在醒后短时间内意识模糊、记忆断片。


## 解决的问题

- 普通手机提醒容易被忽略，无法保证用户真正醒来并执行取药动作。
- 仅依赖软件提示，无法直接阻止安全间隔内的重复取药。
- 用户和家属缺少无需额外操作即可查看的“上次服药时间”。
- 断网、设备离线或提醒未响应时，家属难以区分已完成、未完成和待核查状态。
- 传统药盒缺少设备本地事实记录，难以为后续远程守护和风险判断提供依据。

## 主要功能

- **强震动唤醒**：到达服药时间后触发强震动，持续到实际开盒取药动作完成才停止。
- **上次服药时间常显**：盒体屏幕无需操作，持续显示上次服药时间。
- **安全间隔物理锁定**：未到安全间隔的药格通过机械结构锁定，直接阻止重复取药。
- **开盒轨迹记录**：根据“闭合 → 目标档稳定 → 闭合”的完整轨迹形成开合推定。
- **本地离线提醒**：不依赖手机在线状态，设备具备有效计划和时间质量时可本地提醒。
- **事件补传与状态同步**：网络恢复后按原事件身份补传，云端进行幂等归档和冲突隔离。
- **患者端与家属端协同**：患者端查看今日计划和设备状态，家属端查看进度、风险事件、最后同步时间和处理状态。

## 技术方案

伴药采用“智能药盒 + 患者端/家属端小程序 + 云端业务服务”的端云一体方案：

- **硬件**：ESP32-S3 主控、RTC、五档滑盖检测、屏幕、强震动/声光输出和安全间隔机械锁定结构。
- **患者端**：展示今日计划、倒计时、设备状态、开合推定和历史记录。
- **家属端**：展示守护对象进度、异常事件、数据新鲜度、通知回执和电话确认入口。
- **云端**：负责账户家庭、计划与装药批次、提醒状态机、事件归档、通知编排、权限和审计。
- **设备通信**：比赛样机阶段采用 BLE、POD UART、HTTPS 和受控共享 4G；MQTT 不作为当前已实现能力表述。
- **可靠性**：事件使用 `producer + device_id + boot_epoch + seq` 标识，同 ID 同内容幂等，同 ID 异内容隔离待核查。
- **医疗边界**：开盒只能形成开合推定，不等同于吞服证明、药品识别、剂量判断或医疗诊断。

伴药围绕“提醒有效性”和“重复用药防护”设计一体化智能药盒：

- **强震动唤醒**：到达服药时间后启动强震动提醒，持续到用户实际开盒取药才停止，减少提醒被忽略的情况。
- **上次服药时间常显**：盒体屏幕无需操作，持续展示“上次服药时间”，降低患者和家属的确认成本。
- **安全间隔物理锁定**：未到安全间隔的药格通过机械结构锁定，直接阻止重复取药，不依赖软件提示或用户自觉。
- **事实与推定分层**：开盒轨迹用于形成“开合推定”，不表述为吞服证明、药品识别或患者清醒证明。
- **断网可恢复**：设备本地完成提醒和事件保存，网络恢复后按原事件身份补传，并支持云端幂等归档。

## 方案边界

当前方案重点验证：

1. 强震动是否能有效唤醒目标用户。
2. 实际开盒取药后提醒是否可靠停止。
3. 屏幕常显信息是否足够清晰、低操作负担。
4. 机械锁定是否能在安全间隔内阻止重复取药。
5. 结构、电源、器件和 BOM 是否具备原型实现条件。

以下能力暂不作为首版已完成能力：自动识别药品、精确检测吞服、自动决定剂量或补服方案、人体睡眠识别、医疗诊断和治疗建议。
