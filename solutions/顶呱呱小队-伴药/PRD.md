# 醒伴 CareBox 产品需求文档

> 版本：V1.0｜日期：2026-10-16｜阶段：比赛样机联调与演示

## 1. 产品定位

醒伴是面向需要规律用药的人群及其家属的智能用药提醒与家庭守护系统。它通过电子日仓的本地提醒、开合轨迹和端云同步，让患者少依赖手机，让家属获得可追溯、可分层、带数据新鲜度的远程信息。

产品表达必须遵循：

- “已开盖，形成开合推定”优先于“已服药”。
- 事实、推定、人工确认、模拟数据分层展示。
- 离线、失时、通知未送达和待核查不能被混写成漏服。
- 系统提供提醒与风险沟通，不自动决定剂量、补服方案或诊疗建议。

## 2. 用户与场景

### 2.1 患者

- 不希望频繁操作手机。
- 需要在没有手机或临时无网时仍能获得提醒。
- 需要看到今日计划、倒计时、设备状态和历史记录。

### 2.2 家属

- 需要远程知道每日计划进度、最后同步时间和异常原因。
- 需要在漏服升级或重复取药风险出现时联系患者。
- 需要按角色分配紧急联系人、仅查看和撤权能力。

### 2.3 比赛样机演示

通过两只真实四格电子日仓、一个家庭主体和双端小程序，完成正常提醒、开合推定、漏服升级、重复取药风险、离线待核查和七日视图展示。七日视图中的其余五仓为展示道具。

## 4. 患者端信息架构

- 首页：问候、设备在线、下一次提醒、今日进度。
- 今日计划：时间线、倒计时、目标格、上次开盖时间、提醒状态。
- 记录：日/周/月统计；按时、迟到、漏服、待核查；事实与推定分层。
- 设备：日仓、家庭主体、BLE、4G 附件、电量、固件、同步状态。
- 计划：药物资料、时段、目标格、重复规则、重提策略、安全间隔。
- 我的：资料、家属共享、隐私、提醒方式、库存估算、演示重置。

## 5. 家属端信息架构

- 守护首页：被守护人、今日进度、最后同步、数据新鲜度。
- 动态：回执、风险事件、漏服升级、查看与协助记录。
- 事件详情：发生时间、设备来源、证据层级、渠道回执、处理状态。
- 电话确认：先联系患者；无响应时再联系紧急联系人。
- 家庭成员：紧急联系人、仅查看、邀请、角色调整和撤权。

## 6. 用户使用流程

### 6.1 首次登记与整仓换装

1. 确认空设备、设备身份和当前会话。
2. 进入维护并持久回读。
3. 清空日仓，创建装药批次，录入四格数量和人工药品资料。
4. 创建或采用计划，写入目标格与有效期。
5. 读取设备持久状态，确认版本、批次、计划一致。
6. 退出维护；异常或中断保持待核查，不自动回滚旧药程。

本版只支持整仓重新装药，不支持部分补药、跨格换药、自动识药和真实库存传感。

### 6.2 正常提醒与开合推定

1. 设备在有效时间质量、计划、供电和输出资格下创建提醒实例。
2. 日仓本地提醒，主体在通信成立时增强声光提示。
3. 读取五档滑盖轨迹并去抖。
4. 仅当出现“闭合 → 目标稳定档 → 闭合”且目标与提醒实例一致时形成一次开合推定。
5. 日仓保存原始事件和推定依据，停止该实例未触发的重提。
6. 手机、主体或 4G 恢复后按原事件身份补传。
7. 云端先归档后返回 durable receipt，家属端显示来源和新鲜度。

### 6.3 漏服与分级追呼

1. 到点提醒患者。
2. 在配置次数与间隔内重提。
3. 到达期限后进入 `timeout_pending_review`，不直接与设备失时混淆。
4. 按通知渠道发送患者和紧急联系人；渠道未达单独显示。
5. 电话流程先联系患者，再联系家属；自动外呼以联调结果为准。
6. 迟到开盖更新同一提醒实例，保留原超时历史。

### 6.4 重复取药风险

1. 对比上一次有效开合推定与安全间隔。
2. 安全间隔内再次开盖不直接判定第二次服药。
3. 记录 `risk_event`，患者端提示风险，家属端进入待确认。
4. 家属可电话确认；人工确认作为追加记录，不覆盖设备原始事实。

### 6.5 离线、失时与恢复

- 无网：设备本地继续；事件进入离线队列；App 展示最后同步时间。
- RTC `stale`：允许按产品策略展示风险，但不应伪装为可信时间。
- RTC `unknown/invalid`：进入 `ClockHold`，不运行猜测药程。
- 恢复网络：原 ID、原内容补传；同 ID 同摘要幂等，异摘要冲突隔离。
- 掉电/重启：只恢复完整且校验通过的状态；不完整事务待核查。

## 7. Demo 验收脚本

1. 展示 08:00 已完成、12:00 倒计时、18:00/22:00 待服。
2. 倒计时归零，药盒本地灯语和提示启动。
3. 正常滑盖后，患者端显示开合推定，家属端收到回执。
4. 模拟 12:00 未开盖，展示三次重提、超时、患者追呼和家属兜底。
5. 模拟安全间隔内再次开盖，展示重复取药风险与电话确认。
6. 展示设备离线、最后同步和待核查，不把离线直接判为漏服。
7. 展示七日视图并明确“两真五道具”。

## 8. 明确不承诺

- 不把任意开盖当作服药。
- 不提供吞服证明、药品识别、剂量判断或补服医学建议。
- 不承诺物理时间锁、儿童防护、自动库存传感和人体睡眠/起身识别。
- 不承诺两个日仓同时独立 4G 在线或七仓独立充电、识别、灯控。
- 不承诺音箱已播放的拾音确认。
- 不把现有 HTTPS 写成已实现 MQTT。
- 不把模拟页面、动画或按钮当成实板、服务端或端到端验收证据。

## 9. 验收原则

验收记录至少包含版本、设备、条件、操作、原始证据、结果和未覆盖项。P0 顺序为：

1. 身份、启动代次、断电恢复和安全通信。
2. 时间质量、计划采用、整仓换装和精确回读。
3. 五档滑盖去抖与完整轨迹只生成一次推定。
4. 离线记录、补传、幂等和冲突隔离。
5. 家属端来源、新鲜度和通知证据。

具体场景采用硬件 PRD 中的 T01-T20 矩阵；蜂鸣/ERM、机械、续航、主体与两仓联调在有实测记录前不得标注为已通过。
